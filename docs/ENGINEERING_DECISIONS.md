# Engineering Decisions

## 为什么选择 Vite + Capacitor

最初需求是平板端快速迭代，并且需要最终生成 APK。相比完全原生 Android，从 Web 技术栈起步可以更快验证双栏阅读、批注和统计界面；Capacitor 则负责补齐 Android 打包能力。

## 为什么做本地优先

这是个人学习工具，学习记录、批注和错题数据不需要依赖远端服务才能使用。采用本地优先有三个直接收益：

- 离线可用；
- 减少账号和后端系统复杂度；
- 个人学习数据更容易控制。

## 为什么保留多格式导入

真实学习资料的来源并不统一。PDF、DOCX、TXT、ZIP 和 JSON 各自代表不同资料来源，因此项目没有把自己限定成固定题库，而是把“导入与结构化”作为核心能力之一。

## 当前技术债

- `src/app.js` 体积较大，后续需要模块化；
- parser 层需要更完整的测试；
- 扫描 PDF 仍依赖外部 OCR；
- 本地数据缺少正式 schema migration；
- Android 端还需要更多设备兼容性测试。

## 下一阶段

优先级排序：

1. parser 单元测试；
2. 题库 schema 校验；
3. 学习数据版本迁移；
4. 异常导入恢复；
5. 阶段学习报告导出。
